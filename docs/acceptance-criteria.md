# 验收标准草案

基线审查日期：2026-10-21（Asia/Shanghai）；验证边界同步：2026-10-27。对应[需求基线](requirements.md)。最初文档整理仅静态核对；后续 Jev 定向测试及生产最小链路已有执行证据，见[验证报告](verification-report.md)。这些局部结果不代表下列完整场景均已验收。

以下 Given / When / Then 是根据当前代码整理的可验证场景。对于权限、异常响应、会话创建取舍、恢复目标等未确定规则，Then 表示建议的目标，需业务确认后再作为正式交付标准。Jev 代码已提交并部署，保持关闭；测试结果、真实服务验证和完整业务验收分别记录，不能相互代替。

## 执行和记录约定

- `待执行`：完整场景尚未全部执行或验收；局部测试、发布冒烟等已有结果仍保留在验证报告，不能将其扩大为整项通过。
- `待业务确认`：目标规则未确认或实现存在已知缺口，先确认目标，再决定修复和验证范围。
- 每次执行记录代码版本/工作区差异、环境、输入、脱敏输出、实际结果和证据位置，统一写入[验证报告](verification-report.md)。失败或环境不具备时保留 `FAIL` / `BLOCKED` / `NOT_RUN` 及原因。
- 使用隔离数据库、对象/向量存储和假凭据；需真实模型、MCP 或外部解析服务的场景，按[测试计划](test-plan.md)确认依赖后执行。不要通过全目录测试发现默认运行历史示例脚本；其中部分会访问外部服务或输出配置。
- 表中“已有测试”只说明静态发现的针对性覆盖，测试初始化仍可能读取配置；最终执行命令和隔离方式以测试计划为准。人工/集成场景没有对应自动化时明确写“缺口”。

## 身份、模型与 Agent

### AC-001 注册和登录

需求：`REQ-001.1`。状态：**待执行**；首个账户管理员策略为**待业务确认**。

- **Given**：隔离的用户库和 Redis，分别准备首次注册、普通注册、重复用户名、用户名超过当前 20 字符限制、错误密码和禁用账户。
- **When**：调用注册和登录接口，并使用登录返回的身份继续请求受保护接口。
- **Then**：有效用户能够获得登录结果；重复/超长用户名、错误密码及禁用账户被拒绝且不产生额外用户。记录首个账户角色和后续账户角色，与确认后的注册策略一致。错误响应的 HTTP 与业务状态均需保存。
- **验证方法 / 覆盖**：接口集成、隔离库查询及页面冒烟；缺少专用注册/登录回归测试，不能以路由存在替代证据。

### AC-002 登录态和受保护接口

需求：`REQ-001.2`、`REQ-001.3`。状态：**待业务确认**。

- **Given**：无 token、失效/伪造 token、有效账户及 Redis 当前会话变化等输入；按确认后的策略区分公开和受保护接口。
- **When**：分别请求用户资料修改/查询、对话、模型、工具、知识库、工作台和统计等入口。
- **Then**：受保护接口仅接受有效身份，拒绝不合法身份时不读取或修改资源；公开接口符合批准的例外清单。前端有本地 token 不应使后端绕过认证。
- **验证方法 / 覆盖**：逐路由认证矩阵集成测试；缺少统一认证回归。已知 `/user/update`、`/user/info` 未声明登录依赖，不能假定已满足目标。

### AC-003 跨用户资源隔离

需求：`REQ-001.3`、`REQ-002.2`、`REQ-003.4`、`REQ-004.4`、`REQ-005.4`、`REQ-006.4`、`REQ-007.4`。状态：**待业务确认**。

- **Given**：普通用户 A/B、管理员和分别归属 A/B 的模型、Agent、Skill、对话/历史、知识库/文件、工具、MCP 配置、工作台会话；另列出允许共享的资源。
- **When**：A 使用 B 的 ID 进行查看、续写、更新、删除、检索和导出，管理员执行相同矩阵。
- **Then**：每个操作符合确认后的所有权、共享和管理员规则；被拒绝操作不泄露内容、不改数据。记录“不存在”和“无权限”的实际返回，按确认的响应契约核对。
- **验证方法 / 覆盖**：接口集成与数据前后快照。`TEST-BE-002` 的 [Chunk 测试](../src/backend/agentruler/test/test_chunk_browser.py)含部分文件隔离断言；其他资源存在覆盖缺口。历史、Skill、工作台按 ID 查询及直接检索为静态发现的重点缺口。

### AC-004 模型生命周期

- **Then**：列表及搜索反映正确配置和可见范围，调用使用选定模型；失败有可识别错误，不将其他用户凭据暴露给调用方。被引用模型的删除行为符合确认规则。
- **验证方法 / 覆盖**：假提供商集成测试与页面冒烟；缺少完整生命周期自动化。Skill 测试里的假模型调用只覆盖特定结构化请求，不覆盖模型管理。

### AC-007 Skill 内容维护

需求：`REQ-003.3`、`REQ-003.4`。状态：**待业务确认**。

- **Given**：用户自己的 Skill 默认文件树及另一用户的 Skill；确认支持的层级、文件编码、重复名和被引用时删除规则。
- **When**：在支持目录新增、上传、修改、删除文本文件；提交不存在路径、非 UTF-8 内容、重复名称和跨用户请求，并重新读取。

## 对话与知识库

### AC-008 普通对话流和消息保存

需求：`REQ-004.1`、`REQ-004.2`。状态：**待执行**。

- **Given**：当前用户的 Agent/对话和输出固定内容的假模型，准备普通文本及可选文件 URL 输入。
- **When**：向 `POST /api/v1/completion` 发送问题，收集完整 SSE，再读取对话历史。
- **Then**：返回可解析的流事件，前端拼接的回答与事件内容一致；用户输入和助手回答持久化到正确对话，工具等非文本事件保存在对应历史记录中；不使用过时的 `/api/v1/chat` 作为验收入口。
- **验证方法 / 覆盖**：SSE 接口集成、页面冒烟和隔离库查询；缺少完整普通对话回归，历史 `test_chat.py` 等脚本不作为此闭环已覆盖的证据。

### AC-009 多轮上下文和恢复

需求：`REQ-004.2`、`REQ-004.4`。状态：**待执行**；记忆保留/删除策略为**待业务确认**。

- **Given**：含可辨识上一轮内容的对话；分别配置记忆开启/关闭，隔离摘要和记忆存储。
- **When**：连续提问、刷新前端/重新进入会话，再发起需要历史信息的问题；另以 B 身份请求 A 的历史。
- **Then**：历史归属和顺序正确，模型收到符合当前实现的短期上下文、摘要与可选长期记忆；关闭记忆时不调用长期记忆读写。跨用户请求符合 `AC-003`，不因历史恢复泄露信息。
- **验证方法 / 覆盖**：假模型捕获输入、存储桩调用断言及页面集成；缺少该组合回归，不能从记忆开关字段推定行为通过。

### AC-010 流中断、模型/工具失败与重试

需求：`REQ-004.3`。状态：**待业务确认**。

- **Given**：可控延迟的流和能够抛出错误的模型/工具桩；先确认部分回答保存、错误展示和重试语义。
- **When**：正常结束、浏览器取消、连接断开、模型失败、工具失败后分别检查历史与后续重试。
- **Then**：取消能触发收尾，前端解除等待状态，用户能够区分完成、取消和失败；部分回答、摘要/记忆写入及重试记录符合确认规则，不把中断内容标作完整成功结果。
- **验证方法 / 覆盖**：故障注入与 SSE/数据库联合验证；缺少完整断流回归。`finally` 保存助手消息是代码事实，不代表异常语义已正确。

### AC-011 知识文件入库和删除

需求：`REQ-005.1`、`REQ-005.2`、`REQ-005.4`。状态：**待执行**；文件支持及重试规则为**待业务确认**。

- **Given**：测试知识库、对象存储、向量库和受控解析/嵌入服务；准备一份受支持且包含唯一测试语句的文件、损坏文件及不支持类型。
- **When**：上传后通过返回 URL 创建知识文件，轮询状态，核对解析/向量结果，再删除；模拟下载、解析、嵌入失败。
- **Then**：成功文件能进入可检索状态，状态和文件记录一致；失败不伪装成功，按确认策略保留诊断/重试入口；删除后的元数据、对象与向量处理符合确认的保留规则。创建和删除均受资源权限约束。
- **验证方法 / 覆盖**：隔离存储集成、状态检查和删除前后快照；历史解析/RAG 示例不能替代此流程，缺少完整回归。

### AC-012 知识检索和边界

需求：`REQ-005.2`、`REQ-005.4`。状态：**待业务确认**。

- **Given**：A/B 的独立知识库、已知命中片段与空库，明确检索接口的公开/私有策略。
- **When**：直接检索一个/多个知识库，并通过绑定知识库的 Agent 查询；提交不存在和他人知识库 ID。
- **Then**：有效检索仅返回授权范围内结果，空库/无匹配有一致响应；越权不返回文本、摘要或向量。命中正确率与排序目标需使用确认后的样本集制定，本草案不设数值指标。
- **验证方法 / 覆盖**：确定性嵌入/排序桩、接口集成和人工样本评估；当前直接检索接口缺少登录依赖，相关授权自动化存在缺口。

### AC-013 Chroma Chunk 查看、向量和导出

需求：`REQ-005.3`、`REQ-005.4`。状态：**待执行**。

- **Given**：Chroma 测试集合中同一知识库含多个文件、正文和摘要记录；另准备空/不存在文件及他人文件。

- **验证方法 / 覆盖**：`TEST-BE-002`：[Chunk 测试](../src/backend/agentruler/test/test_chunk_browser.py)覆盖临时 Chroma 分页、搜索、向量、导出、部分权限/参数/不存在场景；非 Chroma 与前端展示仍需补验。

### AC-015 MCP 导入、调用和代理访问

需求：`REQ-006.2` 至 `REQ-006.4`。状态：**待业务确认**。

- **Given**：本地受控 MCP 服务，支持批准的传输协议，两个用户具有不同配置；确认代理入口的鉴权与调用授权规则。
- **When**：导入配置、发现工具、更新/删除服务，在 Agent/工作台调用，并以无凭据、错误凭据及另一用户凭据访问代理；补充服务不可达和工具失败。

- **验证方法 / 覆盖**：受控 MCP 集成与调用日志/桩断言；现有参数/Schema 测试不覆盖认证。已知代理 `check_auth()` 直接返回 `True`，本场景不能登记为已满足。

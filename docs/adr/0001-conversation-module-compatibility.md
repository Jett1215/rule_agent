# ADR 0001 会话模块合并与数据兼容

日期：2026-10-27（Asia/Shanghai）。状态：ACCEPTED。

依据：用户在确认“会话模块包含日常对话与灵寻 LingSeek”的方案后明确要求实施。以下为本次 CONV-001 授权范围内选定的增量实现，未扩大为生产发布或数据库迁移决定。

## 背景与约束

工作台使用 `workspace_session`，智能体会话使用 `dialog/history`，两者已有独立历史、执行链和 SSE 协议。产品需要统一入口与历史，并让新日常会话选择模型、工具、MCP 和智能体；原始数据、旧链接和智能体能力需要保持可用。

## 候选与选择

直接统一数据表及执行链需要迁移既有记录、摘要与记忆，并重新验证 LingSeek 和智能体流程。只修改菜单不能提供配置继承、统一历史及流隔离。因此本次选择统一前端壳，保留两套既有数据存储与执行链，增加必要的服务适配。

新日常会话仍写 `workspace_session`：通用助手使用 WorkSpaceSimpleAgent，选择智能体时复用 GeneralAgent。模型/工具/MCP 覆盖仅作用于当前会话，提示词、知识库、Skill 和记忆开关来自智能体定义。`contexts[].config` 保存资源标识，`agent_events` 保存安全进度；不增加持久列。记忆使用 `workspace:{user_id}:{session_id}` 隔离命名空间。

旧智能体会话继续在统一壳中使用原 `/completion` 和智能体配置，提供另开可配置会话的入口。历史列表以来源前缀区分相同 ID，恢复和删除分派至原接口。旧 `/workspace` 路径通过别名保留。

## 协议与权限

日常工作台 SSE 保持现有事件，新增 `agent_event`、安全 `error`，并在生成和持久化成功后发送 `done`。新前端要求完成标记，拒绝将无标记 EOF 视作成功；取消及切页清理所属流，生成请求不自动重放。

新旧会话执行路径校验所有者及关联资源；工作台 JSON 追加在行锁事务中重新核验当前所有者。本次修复局部边界，SEC-001 的其他资源和代理鉴权缺口继续单独跟踪。

## 兼容与回退

现有表、记录 ID、Agent 定义、真实配置及旧记忆不迁移。旧上下文缺配置时前端明确提示使用当前选择。旧智能体会话继续沿用原配置，当前会话覆盖能力应用于新日常工作台会话。

新前端依赖日常 SSE 的 `done`，发布时必须与支持该事件的后端配套。回滚旧版本虽然可以读取旧 JSON 列，但不会理解新增的智能体选择配置；新配置会话的后续行为及原始数据保留需在发布/回滚前专项核对。本轮仅本地开发与隔离验证，未执行部署或生产数据操作。

## 验证与关联

定向测试覆盖历史和旧链接、配置继承/覆盖/恢复、权限拒绝、完成/失败/取消；浏览器使用构建产物与同源 Mock API。真实数据库、模型、MCP 和记忆集成尚未执行，实际数量、命令与限制见[验证报告](../verification-report.md#2026-10-27-会话模块合并)。

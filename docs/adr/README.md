# 架构决策记录

本目录保存具有长期影响的架构决定，例如核心存储、认证边界、Agent 执行方式、协议兼容和部署拓扑变化。普通修复、执行日志和任务进度分别写入对应文档，不要求每个小改动创建 ADR。

当前只建立记录规则，没有倒填历史已接受决策。现有技术选择和代码事实见[架构](../architecture.md)；无法证实的历史理由不得编造。

## 文件与状态

文件使用 `0001-简短主题.md` 等顺序编号。状态使用 `PROPOSED`、`ACCEPTED`、`REJECTED`、`SUPERSEDED`；`ACCEPTED` 需要真实决策依据。影响重大架构、生产数据、权限或成本的决定须有用户明确授权，不能因创建文档视为同意。

被替代记录保留并链接新 ADR；状态变化时写明日期与依据。不要为了描述现状而声称某个过去日期已经批准。

## 单份记录的内容

1. 标题、编号、提出日期、状态、决策参与者或确认依据。
2. 背景、问题、约束及关联需求/任务。
3. 候选方案，包括维持现状的成本与影响。
4. 选择及理由，明确已知事实、取舍和待验证假设。
5. 受影响模块、接口、数据兼容、迁移及回滚安排。
6. 验证方法、结果或待执行事项。
7. 相关文档与替代关系。

方案尚未确认时保持 `PROPOSED`。确认后同步架构及实施计划，并在[项目状态](../project-status.md)保留导航。
